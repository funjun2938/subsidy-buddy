# 신청서 작성 스튜디오 설계 (Doc Studio)

> 브랜치: `feat/doc-studio` · 작성일: 2026-06-13
> 목표: `/generate`(1647줄 모놀리식)를 **좌 챗봇 / 우 라이브 문서 프리뷰** 전면 화면으로 재설계.
> 핵심 제약: **공식 문서이므로 양식(표/칸 구조)은 절대 수정 불가, 내부 "값"만 사용자가 편집**.

---

## 1. 범위 / 결정 사항

- `/generate` **전면 교체** (별도 라우트 아님). 원래 대주제 "문서작성 별도 페이지 고도화"의 귀결.
- 앱 **기본 테마 light** (`next-themes` defaultTheme).
- 양식 진입은 **기존 흐름 유지**: 지원사업 선택 → 공고 첨부 `.hwp/.hwpx` 자동 로드 또는 직접 업로드 → 스튜디오 진입.
- 챗봇 명령 = **자유대화 + 자동채우기** 둘 다.
- 프리뷰는 **chat 주도 + 값 셀 직접 클릭 편집**(v1 포함). 둘 다 값만 바꾸고 구조 불변.
- 전체 화면 꽉 차는 split 레이아웃, 밝은 모드.

## 2. "양식 불변, 내용만" 보장 — 불변 구조 + 값 맵

열기 시점에 양식을 **한 번만** 파싱해 두 가지로 분리한다.

```ts
// 불변 — 열기 1회 생성 후 절대 변경 안 함
interface DocStructure {
  format: "hwp" | "hwpx";
  title?: string;
  tables: {
    index: number; nrows: number; ncols: number;
    cells: {
      ref: string;        // 통일 ref "t0.r1.c1"
      row: number; col: number;
      label: string;      // 셀 원본 텍스트(라벨/안내문/헤더)
      isFillable: boolean; // 값이 들어갈 칸인가(라벨 인접 빈/값 셀)
      labelFor?: string;   // 이 값 셀이 대응하는 라벨 텍스트
    }[];
  }[];
  // 표 밖 문단(제목/안내문)도 순서 보존용으로 포함
  blocks: { kind: "paragraph" | "table"; text?: string; tableIndex?: number }[];
}

// 변동 — 사용자가 채운/수정한 값. 키는 fillable 셀 ref 만 허용.
type ValueMap = Record<string /*cellRef*/, string>;
```

- **프리뷰 = DocStructure(불변) + ValueMap(오버레이)**. 구조를 건드리는 연산 자체가 API에 없음 → 셀 추가/삭제·표 변경 **불가능**.
- **통일 셀 ref** `t{tableIndex}.r{row}.c{col}` — HWP/HWPX 공통. 어댑터의 셀 좌표(row/col)로 생성. LLM·프리뷰·채우기 전부 이 ref로만 소통.
- 이를 위해 `FormCell` 인터페이스에 `readonly row`/`col` 노출(현재 HWPX `Cell.row/col`, HWP `HwpFormCell.r/c` → `row/col`로 통일).

## 3. 컴포넌트 (모놀리식 해체)

```
app/generate/page.tsx               — 스튜디오 셸: 레이아웃 + 상태 오케스트레이션(슬림)
app/generate/components/
  StudioEntry.tsx     — 양식 진입(공고 선택/첨부 자동로드/직접 업로드). 기존 page.tsx 로직 이전.
  ChatPanel.tsx       — 좌측: SummaryBubble + MessageList + CommandInput
  SummaryBubble.tsx   — 현재 입력 요약(입력됨/미입력 그룹)
  DocPreview.tsx      — 우측: DocStructure+ValueMap → HTML 표 라이브 렌더, 값 셀 클릭 편집
app/generate/hooks/
  useDocSession.ts    — { structure, valueMap, messages, history }, sendCommand/editCell/undo/exportDoc
app/generate/lib (or lib/)
  doc-structure.ts    — FormDoc → DocStructure 빌더, applyValues(valueMap → 채운 bytes)
```

각 단위 책임:
- `useDocSession`: 세션 상태의 단일 소유자. 구조는 read-only로 들고, valueMap만 갱신. 명령/편집/되돌리기/내보내기 액션 노출.
- `DocPreview`: 순수 표시 + 값 셀 onClick→인라인 input→valueMap 갱신 콜백. 구조 변경 API 없음.
- `ChatPanel`: 명령 입력→useDocSession.sendCommand, 응답 말풍선 표시.

## 4. API (서버 무상태)

원본 파일 bytes는 **클라이언트가 보유**(업로드/첨부 다운로드한 것). export 때만 재전송 → 서버 세션 불필요.

| 엔드포인트 | 입력 | 출력 | 비고 |
|---|---|---|---|
| `POST /api/doc/open` | multipart: 양식 파일 | `{ structure: DocStructure, format, initialValues: ValueMap }` | `openFormDoc` + `doc-structure` 빌더. initialValues=기존 셀 텍스트(보통 빈칸) |
| `POST /api/doc/command` | `{ fillable:[{ref,label,value}], valueMap, command, bizInfo }` | `{ changes:[{ref,value}], reply }` | LLM 해석. **바이너리 미접촉.** 응답 ref가 fillable 집합에 없으면 서버가 폐기 |
| `POST /api/doc/export` | multipart: 원본양식 + `valueMap`(JSON) | `filled.hwp`/`filled.hwpx` (또는 zip) | `applyValues(doc, valueMap)` → `toBytes`. fill-core/어댑터 재활용 |

- 기존 `/api/fill-hwp-ai`는 한동안 유지(하위호환) 또는 export로 흡수 — 구현 단계에서 결정.
- `runtime = "nodejs"` (HWP시 cfb/pako). 공고 첨부 다운로드는 기존 `/api/download-attachment`(edge) 그대로.

## 5. 명령 처리 (LLM)

- 입력 컨텍스트: fillable 셀 목록(ref+label+현재값) + 사용자 명령 + bizInfo(사업정보).
- 출력: `{ changes:[{ref, value}], reply }` (JSON only).
- 명령 유형:
  - 단일 수정: "주소를 서울 강남으로" → 해당 라벨 셀 1개.
  - 재작성: "사업 개요 더 구체적으로" → 그 값 셀 내용 재생성.
  - 일괄: "사업정보 보고 다 채워줘" → 여러 ref. (기존 `fill-hwp-ai`의 라벨→답변 로직 일반화 재사용)
  - 비우기: "신청금액 비워줘" → `{ref, value:""}`.
- **안전장치**: 서버가 `changes`의 ref를 fillable 집합으로 필터(미존재/라벨셀 ref 폐기) → LLM이 구조를 못 건드림.
- Gemini→Claude 폴백은 기존 `runLLM` 재사용.

## 6. 프리뷰 렌더 / 직접 편집

- `DocPreview`가 `structure.blocks` 순서대로: paragraph→텍스트, table→`<table>`.
- 셀 상태 색: 라벨/헤더=회색, 값 입력됨=노랑, 방금 변경=파랑(수초 후 페이드), 미입력=회색 placeholder.
- **값 셀 클릭 편집(v1)**: `isFillable` 셀 클릭→인라인 `<input>`/`<textarea>`→blur/Enter 시 valueMap 갱신(=명령과 동일 경로). 라벨/헤더 셀은 편집 불가(클릭 무반응).
- 우상단 배지 "🔒 양식 고정 · 내용만 편집".

## 7. 되돌리기 / 에러

- `useDocSession`이 valueMap 변경마다 히스토리 스택 push. "되돌려줘" 명령 또는 ⨯ 버튼 → 직전 상태 복원.
- 명령 이해 실패(LLM 파싱/빈 changes) → 어시스턴트 말풍선 "이해 못 했어요, 다르게 말해줄래요?".
- export 실패 → 토스트 + 원인. 미입력 칸 있어도 export 허용(경고만).

## 8. 라이트 모드 기본

- `ThemeProvider` defaultTheme="light", `enableSystem` 검토.
- 다크 하드코딩 스타일 **감사 태스크**: 스튜디오 페이지는 light-first로 신규 작성. 공용 컴포넌트(Header/Footer/Auth 등)는 CSS 변수 토큰으로 light 정상 표시 확인, 하드코딩 다크색(`bg-white/5` 등) 발견 시 토큰화. 범위가 커지면 별도 PR로 분리 가능.

## 9. 테스트 (bun, `tests/`)

- 단위: `doc-structure` 빌더(FormDoc→DocStructure, fillable 판정, ref 생성), `applyValues`(valueMap→채운 bytes→round-trip 값 보존), 명령 ref 검증(미존재 ref 폐기).
- 통합: `/api/doc/open`→`command`(mock LLM 또는 실제)→`export` round-trip을 createHwp 합성 양식으로.

## 10. 비범위 (YAGNI)

- 한컴 픽셀 퍼펙트 렌더링(구조 재구성으로 충분). 이미지/도형 편집. 표 구조 편집. 멀티유저 동시편집. PDF 동시출력(별도).

## 11. 오픈 이슈

- HWPX 셀에 통일 ref(`t.r.c`) 부여 시 병합셀(rowspan/colspan) 좌표 정합 — 빌더에서 `cellAt(row,col)` 기준으로 처리.
- `/api/fill-hwp-ai` 유지 vs export 흡수 — 구현 1단계에서 확정.
